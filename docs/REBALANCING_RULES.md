# REBALANCING_RULES — 자산배분·재배분 규칙

최종 갱신: 2026-10-26
원칙: 이 문서는 wiki(Agent 컨텍스트). 비율 계산·수량 산출은 CALCULATION_RULES.md 공식을 코드로. 판단 조건(임계치·한도·제도 제약)은 deterministic logic으로 검증한다. 전략과 종목은 사용자가 정한다 — Agent는 추천하지 않는다.

## 1. 전략 템플릿 (사용자가 선택·수정)
비율 숫자의 원천은 `rules/strategies.yaml` 한 곳이다. 이 문서는 전략 이름과 원칙만 적는다 (숫자가 두 곳에 있으면 어긋난다).
- 올웨더(달리오 원형): 주식 / 장기채 / 중기채 / 금 / 원자재 — 비율은 YAML
- K-올웨더(김성일): 사용자가 책 기준으로 YAML에 채움 (예: 한국주식·미국주식·한국채·미국채·금·현금)
- 박곰희 기본형: 사용자가 YAML에 채움
- 직접 설정: 자산군과 비율을 자유 입력. 합계 100% 검증
- 자산군 ↔ 종목 매핑은 `rules/asset_map.yaml`. 미등록 종목은 LLM이 첫 분류를 제안하고 사용자가 확인하면 YAML에 저장, 이후 실행은 YAML만 읽는다 (같은 잔고 → 같은 주문표, 완료 기준 1)

## 1-1. 리밸런싱 단위 = 풀(pool) (2026-10-26)
- `rules/accounts.yaml`의 `pool`이 리밸런싱 단위. 풀마다 전략(자산배분 로직) 하나. 풀에 계좌를 여러 개 넣으면 합산, 하나만 넣으면 계좌별 — 둘 다 같은 코드
- 기본: 같은 주머니·같은 소유자·같은 세제 구분의 계좌는 한 풀로 **합산**. 예: 미래에셋 연금저축(구)+(신) = `me_pension`. 비중·편차·발동 판단은 합산 기준
- 계좌별로 다른 전략을 쓰고 싶으면 풀을 나눈다 (예: (구)는 올웨더, (신)은 직접 설정)
- 주문은 계좌 단위로 낸다 (계좌 간 자금 이동 불가). 합산 목표 금액을 계좌별로 나눌 때는 같은 자산군 종목이 있는 계좌에서 먼저, 신규 납입은 납입이 들어간 계좌에서. 거래 횟수가 적은 안을 우선
- 계좌마다 종목이 달라도(TIGER vs ACE S&P500) 자산군이 같으면 합산 한 자산군

## 2. 리밸런싱 발동 조건 (deterministic)
- 기본: 자산군 편차 임계치 ±5%p (절대). 2026-10-26 사용자 확정. 상대 25%는 설정 옵션으로만 남긴다
- 주기: 잔고 갱신 시마다 계산, 발동 여부만 판단. 발동해도 사용자 승인 없이는 실행하지 않음
- 최소 거래 금액: 자산군당 10만원 미만 거래는 생략 (수수료·호가 단위 대비 비효율)
- 신규 납입이 있으면 매도 없이 매수만으로 맞추는 안(현금흐름 리밸런싱)을 먼저 계산하고, 그래도 임계치를 넘는 자산군만 매도 포함 안 제시

## 3. 계좌별 제도 제약 (주문 전 코드로 검증, 실패 시 주문표 생성 중단 + 이유 표시)
- 연금저축펀드: 국내 상장 ETF·펀드만. 레버리지·인버스 ETF 불가. 개별 주식 불가
- IRP: 위험자산 한도 적립금의 70%. 안전자산(예금·채권형·TDF 일부 등) 30% 이상 유지. (한도 완화 논의 중 — 큐레이터가 확인 후 갱신)
- ISA(중개형): 국내 상장 주식·ETF·펀드 등. 의무가입 3년
- 현금 주머니(일반계좌): 제약 없음. 단 해외 ETF 매도 시 양도세 22% 고려 → 손익통산 안내
- 현금 주머니의 레거시 종목은 리밸런싱 계산 대상에서 제외 (태그 legacy=true). 전환 글라이드는 별도 규칙(연 N% 전환, 사용자가 설정)

## 4. "왜 리밸런싱인가" 설명 규칙 (Agent가 매번 붙이는 한 문단의 재료)
- 목적은 수익 극대화가 아니라 "처음 정한 위험 수준 유지"
- 비율이 무너지면 하락장 손실이 계획보다 커진다 → 현재 비율 vs 목표 비율로 가정 하락장(예: 주식 −30%) 손실액을 둘 다 계산해 숫자로 제시 (CALCULATION_RULES)
- 서로 다르게 움직이는 자산을 기계적으로 되돌리면 장기적으로 리밸런싱 보너스
- 연금계좌는 과세이연이라 리밸런싱 비용(세금)이 거의 없다
- 설명은 위 재료 + 이번 편차 수치로 구성. 과장·예측 표현 금지("오를 것이다" 등)

## 5. 사용자 결정 반영
- 제안에 대한 수락/거절/보류와 사유는 DECISIONS.md에 기록
- 같은 자산군에 대해 2회 연속 거절되면 Agent는 다음 제안 시 "지난번 거절 사유"를 먼저 보여주고, 임계치 조정을 제안할 수 있다 (규칙 자체를 바꾸는 건 사용자)
- 전략 변경은 반드시 사용자가 명시적으로. Agent가 전략을 바꾸지 않는다

## 6. 자동주문 단계 (2단계 이후)
- Level 0 드라이런: 주문표만 생성
- Level 1 승인형: 사용자가 주문표를 승인하면 실행
- Level 2 자동: 임계치 발동 + 한도 내면 자동 실행, 실행 후 알림
- 공통 안전장치: 1회 주문 금액 한도, 일일 한도, 장중 시간(09:00~15:20) 제한, 모든 주문 요청·응답 로그 DB 저장, 실패·부분체결 시 알림 후 중단
