# REBALANCING_RULES — 자산배분·재배분 규칙

최종 갱신: 2026-10-26
원칙: 이 문서는 wiki(Agent 컨텍스트). 비율 계산·수량 산출은 CALCULATION_RULES.md 공식을 코드로. 판단 조건(임계치·한도·제도 제약)은 deterministic logic으로 검증한다. 전략과 종목은 사용자가 정한다 — Agent는 추천하지 않는다.

## 1. 전략 템플릿 (사용자가 선택·수정)
비율 숫자의 원천은 `rules/strategies.yaml` 한 곳이다. 이 문서는 전략 이름과 원칙만 적는다 (숫자가 두 곳에 있으면 어긋난다).
- 올웨더(달리오 원형): 주식 / 장기채 / 중기채 / 금 / 원자재 — 비율은 YAML
- K-올웨더(김성일): 사용자가 책 기준으로 YAML에 채움 (예: 한국주식·미국주식·한국채·미국채·금·현금)
- 박곰희 기본형: 사용자가 YAML에 채움
- 직접 설정: 자산군과 비율을 자유 입력. 합계 100% 검증
- 자산군 ↔ 종목 매핑은 `rules/asset_map.yaml`. 미등록 종목은 LLM이 첫 분류를 제안하고 사용자가 확인하면 YAML에 저장, 이후 실행은 YAML만 읽는다 (같은 잔고 → 같은 주문표, 완료 기준 1)

## 1-1. 리밸런싱 단위 = 풀(pool) (2026-10-26)
- `rules/accounts.yaml`의 `pool`이 리밸런싱 단위. 풀마다 전략(자산배분 로직) 하나. 풀에 계좌를 여러 개 넣으면 합산, 하나만 넣으면 계좌별 — 둘 다 같은 코드
- 기본: 같은 주머니·같은 소유자·같은 세제 구분의 계좌는 한 풀로 **합산**. 예: 미래에셋 연금저축(구)+(신) = `me_pension`. 비중·편차·발동 판단은 합산 기준
- 계좌별로 다른 전략을 쓰고 싶으면 풀을 나눈다 (예: (구)는 올웨더, (신)은 직접 설정)
- 주문은 계좌 단위로 낸다 (계좌 간 자금 이동 불가). 합산 목표 금액을 계좌별로 나눌 때는 같은 자산군 종목이 있는 계좌에서 먼저, 신규 납입은 납입이 들어간 계좌에서. 거래 횟수가 적은 안을 우선
- 계좌마다 종목이 달라도(TIGER vs ACE S&P500) 자산군이 같으면 합산 한 자산군

## 1-2. 종목 선택 규칙 (2026-10-26 사용자: 룰을 조사해 기본값을 두고 바꿀 수 있게)
- 같은 자산군의 **기존 보유 종목**이 그 계좌에 있으면 그 종목으로 사고판다 (종목 수를 늘리지 않는다). 예외(2026-10-26 사용자): 전략이 `instruments`로 종목을 지정한 자산군은 **매수는 지정 종목으로** 간다 — 보유 종목이 있어도. 매도는 여전히 보유 종목(위성 먼저). 예: 올웨더 중기채는 보유 ACE 종합채권을 중기채로 세되 추가 매수는 ACE 국고채10년
- 없으면 기본 종목을 두 층으로 찾는다 (2026-10-26 사용자: 종목 유형은 전략이 정한다): ① 전략이 지정한 종목 `rules/strategies.yaml` 해당 전략의 `instruments`(자산군별 국가·만기·환노출 유형 + 종목코드) ② 전략에 지정이 없으면 `rules/asset_map.yaml`의 `class_defaults` 공통 기본값. 같은 "장기채"라도 올웨더(달리오)는 미국 국채 20~25년, K-올웨더는 한국·미국 국채이므로 전략이 유형을 정하고, 유형 안에서 종목 하나는 아래 기준으로 고른다
- 기본 종목 고르는 기준 (위키 `docs/wiki/products/`에서 비교): ① 계좌 적격(연금저축: 국내 상장, 레버리지·인버스 제외) ② 현물·실물형 > 선물형(롤오버 비용) ③ 환노출 여부는 전략이 정한 대로 ④ 같은 자산군을 **이미 많이 보유한 종목(운용사)** 우선 ⑤ 없으면 거래량(거래대금) 큰 것 ⑥ 그다음 총보수 낮은 것 (2026-10-26 사용자: 보유 수량이 많은 회사를 따르고, 아니면 거래가 많은 쪽. 보수 차이는 미미)
- 종목 역할 `role`: core(핵심, 넓은 지수·기본 종목) / satellite(위성, 테마·특정 국가). 초과 자산군을 팔 때는 **위성부터 전량까지**, 남은 초과분은 핵심을 비례로. 매수는 핵심으로만 (2026-10-26 사용자: 완전 리밸런싱 계좌는 테마를 정리해 전략대로)
- "완전 리밸런싱" 옵션: 임계치를 무시하고 모든 자산군을 목표로 맞춘다. 처음 전략으로 전환할 때 한 번 쓰는 용도
- Agent는 종목을 추천하지 않는다. 기본값과 후보 목록을 보여주고 사용자가 고른다

## 2. 리밸런싱 발동 조건 (deterministic)
- 기본: 자산군 편차 임계치 ±5%p (절대). 2026-10-26 사용자 확정. 상대 25%는 설정 옵션으로만 남긴다
- 주기: 잔고 갱신 시마다 계산, 발동 여부만 판단. 발동해도 사용자 승인 없이는 실행하지 않음. 달력 주기(연 1회·월 1회)는 쓰지 않는다 (2026-10-26 사용자 확정. 저자들은 연 1회·월 1회를 말하지만 밴드 규칙은 없고, 주기별 성과 차이는 일관되지 않음 — wiki/strategies/principles-from-books.md)
- 최소 거래 금액: 자산군당 10만원 미만 거래는 생략 (수수료·호가 단위 대비 비효율)
- 신규 납입이 있으면 매도 없이 매수만으로 맞추는 안(현금흐름 리밸런싱)을 먼저 계산하고, 그래도 임계치를 넘는 자산군만 매도 포함 안 제시

## 3. 계좌별 제도 제약 (주문 전 코드로 검증, 실패 시 주문표 생성 중단 + 이유 표시)
- 연금저축펀드: 국내 상장 ETF·펀드만. 레버리지·인버스 ETF 불가. 개별 주식 불가. 공모 상장 리츠는 가능(금융위 2022-10-07). 근거: 레버리지·인버스 제외와 미수·신용 금지는 금융위 2017-11-21 업무지침(보도자료), 해외 상장·개별 주식 불가는 계좌가 "집합투자증권 중개계약"이라는 구조(소득세법 시행령 §40의2①1나). 위험자산 70% 한도는 연금저축에 없음(퇴직연금 전용) — wiki/sources/pension-account-rules.md
- IRP: 위험자산 한도 적립금의 70% (근로자퇴직급여보장법 시행규칙 §10①2). 안전자산 30% 이상 유지 — 안전자산 = 원리금보장상품, 투자적격 채권형, 주식 비중 50% 미만 혼합형(퇴직연금감독규정 §11①5, 2023-11-16 개정), 적격 TDF, 디폴트옵션, MMF. 편입 불가: 레버리지·인버스 ETF, 파생상품 위험평가액 40% 초과 펀드·ETF(원유·금 선물형 등은 개별 확인), 개별 주식 (감독규정 §9①·§11②). 2026-10-26 현재 70% 시행 중, 폐지·상향 검토는 보류 보도(2026-09-30) — 분기마다 고용부 시행규칙 입법예고 확인
- ISA(중개형): 국내 상장 주식·ETF·펀드 등. 의무가입 3년
- 현금 주머니(일반계좌): 제약 없음. 단 해외 ETF 매도 시 양도세 22% 고려 → 손익통산 안내
- 현금 주머니의 레거시 종목은 리밸런싱 계산 대상에서 제외 (태그 legacy=true). 전환 글라이드는 별도 규칙(연 N% 전환, 사용자가 설정)

## 4. "왜 리밸런싱인가" 설명 규칙 (Agent가 매번 붙이는 한 문단의 재료)
- 목적은 수익 극대화가 아니라 "처음 정한 위험 수준 유지"
- 비율이 무너지면 하락장 손실이 계획보다 커진다 → 현재 비율 vs 목표 비율로 가정 하락장(예: 주식 −30%) 손실액을 둘 다 계산해 숫자로 제시 (CALCULATION_RULES)
- 서로 다르게 움직이는 자산을 기계적으로 되돌리면 장기적으로 리밸런싱 보너스
- 연금계좌는 과세이연이라 리밸런싱 비용(세금)이 거의 없다. 또 인출 제한이 있어 규칙을 지키기 쉬운 계좌다(김성일 "연금은 행동장치")
- 새 돈(납입·분배금)을 가장 부족한 자산군에 넣는 방식이 거래 비용 없이 위험 통제 효과를 대부분 가져간다(Vanguard 2010) → §2 "신규 납입은 매수만 먼저"의 근거
- 리밸런싱 보너스의 크기는 작다: 상관 낮고 변동성 큰 자산 쌍에서 연 0.5%p 안팎(Bernstein 1996, 미국 주식·장기채 연 1회 예시 0.49%p). 주기(월·분기·연)는 어느 것도 일관되게 우세하지 않음. 설명에서 과장하지 않는다
- ±5%p 임계치는 Vanguard 2010이 "연 1회 또는 반기 점검 + 5%p"를 위험 통제와 비용 사이의 합리적 균형으로 결론 낸 숫자와 같다 → "흔히 쓰는 기준"으로 붙일 수 있음. 출처는 wiki/strategies/principles-from-books.md
- 설명은 위 재료 + 이번 편차 수치로 구성. 과장·예측 표현 금지("오를 것이다" 등)
- 전략이 원형과 다른 점은 아래 "우리가 원형에서 바꾼 것"을 근거로 설명한다. Agent는 이 사유를 다시 판단하지 않고 그대로 전달한다 (사용자가 물으면 "왜 그렇게 했는지"를 이 문단으로 답한다)

### 4-1. 우리 올웨더가 원형과 다른 점과 사유 (2026-10-27 사용자 결정, DECISIONS.md)
- **기준 템플릿**: 시그널스노우볼 앱(해빗팩토리)의 "해외 올웨더 포트폴리오" — 미국 대형주 30 / 미국 중기채 15 / 미국 장기채 40 / 금 8 / 원자재 7, 예시 종목까지 그대로. 원형(로빈스 All Seasons 30/40/15/7.5/7.5)과 비율은 같고 금·원자재를 8/7로 반올림한 것. 사용자가 "라이선스 있는 핀테크가 연금계좌용으로 제시한 구성"을 기준으로 삼기로 함.
- **2026-10-26에 정했다가 바꾼 것 세 가지** (Agent가 "왜 바뀌었나"를 물으면 이 문단으로 답한다):
  - 금 15(원자재 합침) → **금 8 / 원자재 7**. 하루 전에는 국내 상장 원자재 바스켓 ETF가 없고 단일 원자재 선물 ETF는 품목 베팅·고비용(0.35~0.83%+롤오버)이라 합쳤다. 바꾼 이유: 원형의 "물가 급등 국면 완충"을 금만으로 대신하지 않고, 앱 예시처럼 원유 선물(KODEX WTI원유선물(H))로 채워 원형 구성을 유지한다. 단일 품목·선물형·연금저축 편입 여부(운용사 안내 1건)라는 한계는 그대로 열린 항목.
  - 장기채 환노출(ACE 미국30년국채액티브 476760) → **환헤지(ACE 미국30년국채액티브(H) 453850)**. 하루 전에는 장기 계좌·헤지 비용·주식 ETF와 일관성 때문에 환노출을 골랐다. 바꾼 이유: 앱 템플릿을 따름. 환헤지는 원화 기준 변동이 작은 대신 한미 금리차만큼 비용이 빠진다. 환노출 476760은 후보로 남긴다.
  - 중기채 ACE 국고채10년(국내) → **KODEX 미국채10년선물(308620)**. 원형의 "미국 국채 7~10년"에 맞춘 것. 선물형·환노출·보수 0.29%. 보유 ACE 종합채권(AA-이상)은 중기채로 계속 세고 팔지 않으며, 추가 매수만 이 종목.
- **종목 선택 룰**: 전략이 자산군의 유형(국가·만기·환)을 정하고, 유형 안에서는 이미 많이 보유한 운용사 → 거래량 → 총보수 순. 같은 지수 ETF끼리 보수 차이는 미미하다(S&P500 0.0047 vs 0.0068%). 그래서 S&P500 기본은 TIGER(보유·거래량), 금 기본은 ACE(보유·규모). 앱이 예시를 둘씩 든 자산군은 첫 번째를 썼다.
- **리밸런싱 기준**: 앱은 "매년 1회 비중 리밸런싱", 우리는 ±5%p 밴드만(2026-10-26 결정). 달력 주기는 쓰지 않는다.

## 5. 사용자 결정 반영
- 제안에 대한 수락/거절/보류와 사유는 DECISIONS.md에 기록
- 같은 자산군에 대해 2회 연속 거절되면 Agent는 다음 제안 시 "지난번 거절 사유"를 먼저 보여주고, 임계치 조정을 제안할 수 있다 (규칙 자체를 바꾸는 건 사용자)
- 전략 변경은 반드시 사용자가 명시적으로. Agent가 전략을 바꾸지 않는다

## 6. 자동주문 단계 (2단계 이후)
- Level 0 드라이런: 주문표만 생성
- Level 1 승인형: 사용자가 주문표를 승인하면 실행
- Level 2 자동: 임계치 발동 + 한도 내면 자동 실행, 실행 후 알림
- 공통 안전장치: 1회 주문 금액 한도, 일일 한도, 장중 시간(09:00~15:20) 제한, 모든 주문 요청·응답 로그 DB 저장, 실패·부분체결 시 알림 후 중단
