# SCREEN_REFERENCE — 화면 설계 레퍼런스

최종 갱신: 2026-10-26
원칙: 화면 하나 = 질문 하나. 화면은 로직이 안정된 뒤 얇게 얹는다. 아래는 (A) 컨셉 이미지 원본 기록, (B) 논의 후 확정된 화면 구성.

## A. 컨셉 이미지 원본 (기존 계정 시안, 텍스트 기록)
원본 이미지는 `docs/assets/concept.jpg`로 repo에 넣어 둘 것.

### 정체성
- 서비스명 둘이서은퇴. 슬로건 "우리의 오늘이, 더 나은 내일이 되도록" / "함께라면, 은퇴도 계획이 됩니다."
- 한 줄: 부부의 모든 자산을 한눈에, 연금·주식·부동산·대출을 통합 관리하고 리밸런싱, 세금, 수령 전략까지 설계해주는 은퇴 가계 노트
- 톤: 바다를 보는 부부 사진, 노을 톤 + 다크 네이비 사이드바 + 흰 카드. 인사말 "지금의 선택이, 10년 후의 삶을 만듭니다."

### 웹 대시보드
- 좌측 메뉴: 홈 / 입력 시트 / 연금 / 주식 / 부동산 / 대출 / 리밸런싱 / 세금 설계 / 설정, 하단 가족 계정
- 뷰 전환: 부부 전체 / 부부 / 나
- KPI 3개: 총 자산 12억 8,450만(+3.2%) / 노후 주머니 4억 2,300만(33%) / 갈아타기 주머니 8억 6,150만(67%)
- 자산 구성 도넛: 주식 37 · 부동산 31 · 연금 16 · 대출 −8 · 현금 8 · 기타 6
- 전략별 배분: 올웨더(달리오) / 박곰희 기본형 / K-올웨더(김성일) → 주식·장기채·중기채·금·원자재 (예 30/40/15/7.5/7.5)
- 은퇴 가능 시점: 목표 만 62세(2036), 현재 40/42세, 목표 자산 30억
- 가구 소득 시뮬레이션 라인차트(2025~2050), 현재 vs 리스크 시나리오, "2036년 연 4,200만원"
- 알림: 연금 비중 목표 미달(12%→25%) / 주식 리밸런싱 필요(편차 ±7.3%) / 사적연금 수령 세금 최적화 가능
- 배너: "지금, 이대로 괜찮을까요? 리밸런싱이 필요해요"

### 모바일
- 총 자산, 두 주머니 원형 게이지, 이번 달 체크리스트(연금 납입 확인 / 주식 리밸런싱 / 대출 상환 점검), 하단 탭 홈·자산·시뮬레이션·공유·더보기

### 4대 기능 카드
1. 간편한 입력(구글시트 연동, 표 편집) 2. 다양한 연동(마이데이터·Drive·Excel·직접 입력) 3. 가족 실시간 공유(남편 대표, 아내 편집 가능, 활동 알림) 4. AI 리밸런싱 & 시뮬레이션(리밸런싱 신호, 갈아타기 역산 "목표 30억까지 월 280만원")

## B. 확정 화면 구성 (메뉴 5 + 설정)

### 홈 — "우리 지금 괜찮아?"
노후 주머니 / 현금 주머니 목표 대비 % 카드. 이번 달 제안 카드 2~3개(예: 연금 주식 비중 +7%, 세액공제 한도 잔여, 연령 트리거 체크리스트). 각 카드 수락/넘김 → DECISIONS 기록. 상단 토글 부부전체/나/배우자.
필요 데이터: 두 주머니 잔고·목표, Agent 제안 큐.

### 입력 — "숫자 넣기 가장 쉬운 곳"
API 연동 계좌는 자동. 캡처 붙여넣기가 가장 큰 버튼. 구글시트·엑셀·직접 편집. 변환 결과 + 자동 태깅(주머니/층/세제구분/레거시) 확인 화면. 계좌별 마지막 갱신일.
필요 데이터: 계좌 목록, 보유 내역, 태그, 갱신 이력.

### 연금 — "결국 매달 얼마 받아?"
부부 각자 4층 석탑, 꼭대기에 "우리 집 예상 월 수령액". 55~90세 연도별 수령 그래프(층별 색, 브릿지 공백 표시). 가정 슬라이더(수익률·물가·수령기간·은퇴 나이).
필요 데이터: 층별 잔고·납입 계획, 국민연금 예상액, CALCULATION_RULES 가정값.

### 리밸런싱 — "지금 뭘 사고팔까?"
전략 선택 → 목표 vs 현재 비율 막대 → 매수/매도 주문표 → "왜 지금" 한 문단(현재 비율로 뒀을 때 하락장 예상 손실 vs 리밸런싱 후) → [승인하고 자동주문] / [직접 주문] → 주문 이력. 레거시 종목 별도 표시.
필요 데이터: 종목 단위 잔고·시세, 전략 목표 비율, 임계치, 제도 제약 검증 결과.

HTML 목업: `docs/assets/mockup-rebalancing.html` (2026-10-26, 브라우저에서 열어 볼 것). 이 한 장이 2주차 Streamlit 화면의 스펙이다. 위에서 아래로:
1. 머리글: 주머니 · 계좌(증권사) / 제목 "지금 뭘 사고팔까?" / 전략 드롭다운(올웨더·K-올웨더·직접 설정) / 잔고 갱신일
2. 경고 배너: "재배분이 필요해요 — 주식 비중이 목표보다 7.3%p 높아요" + "왜 지금" 한 문단(하락장 손실 L_now vs L_target, 과세이연 안내) + 총 평가액(이번 달 납입 포함)
3. 목표 vs 현재: 자산군별 막대 2개(목표·현재) + "30% → 37.3% (+7.3)" + 발동 기준·제도 검증 결과 한 줄
4. 주문표: 구분(매도/매수/생략) · 자산군 · 종목 · 수량 · 예상 금액 · 비고(편차, 납입금 포함, 생략 사유). 매도 먼저, 납입금은 매수에 먼저 사용
5. 지난 결정 한 줄("2026-07 장기채 매수 보류 — 금리 인하 기다림 → 이번엔 편차가 더 커졌어요") + 버튼 [이번엔 넘기기] [직접 주문할게요] [승인하고 자동주문]
목업과 PoC의 차이: 계좌는 한투가 아니라 미래에셋이므로 [승인하고 자동주문]은 비활성(한투 계좌 생기면 활성). 납입은 "이번 달 30만원"이 아니라 첫 시나리오 "IRP 300만원".

### 세금·수령 설계 — "어떻게 받아야 덜 내?" (2단계)
계좌 태그 기반. 개시 나이·순서 드래그 → 연간 세금·실수령액 즉시 반영. 1,500만원 기준선 표시(절벽 아님). 비과세 연금보험은 선 밖. 퇴직금은 실제수령연차 기준 과세 비율 표시.
필요 데이터: 계좌 태그, 수령 계획, TAX_RULES.

### 부동산 — "저 집까지 얼마 모자라?" (2단계)
팔로우 단지 카드(시세·전세가·갭·실거래·뉴스·분양 일정) → 시나리오 비교(실거주 갈아타기 vs 분양권+월세) → 현금 주머니 목표 시점, 노후 주머니 영향.
필요 데이터: 현재 집·대출, 관심 단지, 외부 시세/뉴스.

### 설정
가족 초대코드, 편집 권한, 전략 기본값, 알림 주기, 증권사 API 키·자동매매 한도.

### 계좌 묶기 — "이 계좌들, 같이 볼까 따로 볼까?" (첫 진입·설정, 2026-10-26 사용자 요구)
계좌를 등록한 직후(처음 로그인) 그리고 설정에서 언제든:
1. 계좌를 **풀**로 묶는다: 합산할 계좌는 같은 풀에, 따로 갈 계좌는 각자 풀. 드래그 또는 체크박스
2. 풀마다 **전략**(올웨더 / K-올웨더 / 직접 설정)과 **모드**를 고른다
   - 리밸런싱: 매도·매수로 목표 비율을 맞춘다
   - 매수만: 매도 없이 납입금으로 부족한 자산군만 기계적으로 산다
3. 리밸런싱 화면 상단에 풀 선택 드롭다운. 화면은 선택한 풀 기준으로 그린다
저장 위치: `rules/accounts.yaml`의 `pool` / `pools`. v1(PoC)은 파일 편집, v1.5부터 화면.
