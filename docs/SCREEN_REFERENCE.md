# SCREEN_REFERENCE — 화면 설계 레퍼런스

최종 갱신: 2026-10-27
원칙: 원본 컨셉의 구성·정보 계층·분위기를 실제 화면으로 재현한다. 고정 데모로 디자인을 먼저 검수하고 실데이터와 계산을 연결한다. 작업표는 AGENT_DESIGN §0.

## 현재 화면 검수 기준 — 2026-10-27 사용자 승인

- **시각 원본은 `assets/concept.jpg`**. 중앙 데스크톱과 오른쪽 모바일을 같은 앱의 반응형 화면으로 구현한다. 왼쪽 브랜드 사진·아래 기능 소개는 소개 영역이며, 부부 사진/바다·노을 분위기를 앱 머리글에도 반영한다.
- 데스크톱: 네이비 사이드바·가족 프로필 → 사진/인사말/보기 전환 → KPI 3개 → 자산 도넛/은퇴 카드/알림 → 전략 배분/소득 그래프. 카드 비율·여백·글자 계층·아이콘·색상까지 비교한다.
- 모바일: 총자산 → 두 주머니 원형 카드 → 이번 달 체크리스트 → 상세 보기 → 하단 탭. 데스크톱 메뉴를 단순 압축하지 않는다.
- 검수 크기: 1440/1024/390px, 360px 전체 가로 넘침 검사. 고정 데모·고정 날짜로 스크린샷과 기능 동작을 확인한다. 최초 사람의 컨셉 비교 후 승인된 구현 이미지를 시각 회귀 기준으로 삼는다.
- 원본의 예시 숫자는 실데이터/투자 비율의 원천이 아니다. 총자산·순자산·금융자산 주머니 비율의 분모를 명시하고, 주식 자산군과 연금 계좌 분류를 중복 집계하지 않는다. 부채는 음수 도넛 대신 별도 표시한다.
- 모든 카드에 demo/real/missing/stale/partial 상태와 기준일을 정의한다. 실제 보기에서 배우자 자료가 없으면 ‘미등록’. 원본 예시 금액으로 채우지 않는다.
- 최초 홈 검수본에는 모든 핵심 영역을 구현하되, 미연결 시뮬레이션/메뉴는 데모·준비 상태를 표시한다. 기능 완료와 시각 완료는 별도다.
- 사용자 화면의 YAML 파일명·풀 ID·파일 경로는 진단 영역으로 옮기고 계좌 이름·전략 이름·갱신 시각을 표시한다. 로딩·실패·미등록에서도 레이아웃을 유지한다.
- 구현: React·TypeScript·Vite. Streamlit은 비교 도구로 유지. 세부 제안은 ARCHITECTURE_REVIEW §7.

## A. 컨셉 이미지 원본 (기존 계정 시안, 텍스트 기록)
원본 이미지는 `docs/assets/concept.jpg`에 저장되어 있다. 아래 수치와 문구는 원본의 기록이며, 실제 계산·전략 값은 코드/규칙의 원천을 따른다.

### 정체성
- 서비스명 둘이서은퇴. 슬로건 "우리의 오늘이, 더 나은 내일이 되도록" / "함께라면, 은퇴도 계획이 됩니다."
- 한 줄: 부부의 모든 자산을 한눈에, 연금·주식·부동산·대출을 통합 관리하고 리밸런싱, 세금, 수령 전략까지 설계해주는 은퇴 가계 노트
- 톤: 바다를 보는 부부 사진, 노을 톤 + 다크 네이비 사이드바 + 흰 카드. 인사말 "지금의 선택이, 10년 후의 삶을 만듭니다."

### 웹 대시보드
- 좌측 메뉴: 홈 / 입력 시트 / 연금 / 주식 / 부동산 / 대출 / 리밸런싱 / 세금 설계 / 설정, 하단 가족 계정
- 뷰 전환: 부부 전체 / 부부 / 나
- KPI 3개: 총 자산 12억 8,450만(+3.2%) / 노후 주머니 4억 2,300만(33%) / 갈아타기 주머니 8억 6,150만(67%)
- 자산 구성 도넛: 주식 37 · 부동산 31 · 연금 16 · 대출 −8 · 현금 8 · 기타 6
- 전략별 배분: 올웨더(달리오) / 박곰희 기본형 / K-올웨더(김성일) → 주식·장기채·중기채·금·원자재 (예 30/40/15/7.5/7.5)
- 은퇴 가능 시점: 목표 만 62세(2036), 현재 40/42세, 목표 자산 30억
- 가구 소득 시뮬레이션 라인차트(2025~2050), 현재 vs 리스크 시나리오, "2036년 연 4,200만원"
- 알림: 연금 비중 목표 미달(12%→25%) / 주식 리밸런싱 필요(편차 ±7.3%) / 사적연금 수령 세금 최적화 가능
- 배너: "지금, 이대로 괜찮을까요? 리밸런싱이 필요해요"

### 모바일
- 총 자산, 두 주머니 원형 게이지, 이번 달 체크리스트(연금 납입 확인 / 주식 리밸런싱 / 대출 상환 점검), 하단 탭 홈·자산·시뮬레이션·공유·더보기

### 4대 기능 카드
1. 간편한 입력(구글시트 연동, 표 편집) 2. 다양한 연동(마이데이터·Drive·Excel·직접 입력) 3. 가족 실시간 공유(남편 대표, 아내 편집 가능, 활동 알림) 4. AI 리밸런싱 & 시뮬레이션(리밸런싱 신호, 갈아타기 역산 "목표 30억까지 월 280만원")

## B. 기능별 화면 구성 (메뉴 배치는 위 컨셉 검수 기준 우선)

### 홈 — "우리 지금 괜찮아?"
위 검수 기준의 전체 홈 레이아웃: 총자산과 두 주머니 카드, 자산 도넛, 은퇴 목표, 전략 배분, 소득 전망, 이번 달 제안/체크리스트. 각 제안 수락/넘김 → 결정 기록. 상단 토글 부부전체/나/배우자. 준비된 영역은 실제 API를 연결하고 나머지는 명시적인 데모/미입력 상태로 둔다.
필요 데이터: 두 주머니 잔고·목표, Agent 제안 큐.

### 입력 — "숫자 넣기 가장 쉬운 곳"
API 연동 계좌는 자동. 캡처 붙여넣기가 가장 큰 버튼. 구글시트·엑셀·직접 편집. 변환 결과 + 자동 태깅(주머니/층/세제구분/레거시) 확인 화면. 계좌별 마지막 갱신일.
필요 데이터: 계좌 목록, 보유 내역, 태그, 갱신 이력.

### 연금 — "결국 매달 얼마 받아?"
부부 각자 4층 석탑, 꼭대기에 "우리 집 예상 월 수령액". 55~90세 연도별 수령 그래프(층별 색, 브릿지 공백 표시). 가정 슬라이더(수익률·물가·수령기간·은퇴 나이).
필요 데이터: 층별 잔고·납입 계획, 국민연금 예상액, CALCULATION_RULES 가정값.

### 리밸런싱 — "지금 뭘 사고팔까?"
전략 선택 → 목표 vs 현재 비율 막대 → 매수/매도 주문표 → "왜 지금" 한 문단(현재 비율로 뒀을 때 하락장 예상 손실 vs 리밸런싱 후) → [승인하고 자동주문] / [직접 주문] → 주문 이력. 레거시 종목 별도 표시.
필요 데이터: 종목 단위 잔고·시세, 전략 목표 비율, 임계치, 제도 제약 검증 결과.

HTML 목업: `docs/assets/mockup-rebalancing.html` (2026-10-26). 리밸런싱 정보 순서의 상세 참고이며 공통 외형은 concept.jpg를 따른다. 위에서 아래로:
1. 머리글: 주머니 · 계좌(증권사) / 제목 "지금 뭘 사고팔까?" / 전략 드롭다운(올웨더·K-올웨더·직접 설정) / 잔고 갱신일
2. 경고 배너: "재배분이 필요해요 — 주식 비중이 목표보다 7.3%p 높아요" + "왜 지금" 한 문단(하락장 손실 L_now vs L_target, 과세이연 안내) + 총 평가액(이번 달 납입 포함)
3. 목표 vs 현재: 자산군별 막대 2개(목표·현재) + "30% → 37.3% (+7.3)" + 발동 기준·제도 검증 결과 한 줄
4. 주문표: 구분(매도/매수/생략) · 자산군 · 종목 · 수량 · 예상 금액 · 비고(편차, 납입금 포함, 생략 사유). 매도 먼저, 납입금은 매수에 먼저 사용
5. 지난 결정 한 줄("2026-07 장기채 매수 보류 — 금리 인하 기다림 → 이번엔 편차가 더 커졌어요") + 버튼 [이번엔 넘기기] [직접 주문할게요] [승인하고 자동주문]
목업과 PoC의 차이: 계좌는 한투가 아니라 미래에셋이므로 [승인하고 자동주문]은 비활성(한투 계좌 생기면 활성). 납입은 "이번 달 30만원"이 아니라 첫 시나리오 "IRP 300만원".

### 세금·수령 설계 — "어떻게 받아야 덜 내?" (2단계)
계좌 태그 기반. 개시 나이·순서 드래그 → 연간 세금·실수령액 즉시 반영. 1,500만원 기준선 표시(절벽 아님). 비과세 연금보험은 선 밖. 퇴직금은 실제수령연차 기준 과세 비율 표시.
필요 데이터: 계좌 태그, 수령 계획, TAX_RULES.

### 부동산 — "저 집까지 얼마 모자라?" (2단계)
팔로우 단지 카드(시세·전세가·갭·실거래·뉴스·분양 일정) → 시나리오 비교(실거주 갈아타기 vs 분양권+월세) → 현금 주머니 목표 시점, 노후 주머니 영향.
필요 데이터: 현재 집·대출, 관심 단지, 외부 시세/뉴스.

### 설정
가족 초대코드, 편집 권한, 전략 기본값, 알림 주기, 증권사 API 키·자동매매 한도.

### 계좌 묶기 — "이 계좌들, 같이 볼까 따로 볼까?" (첫 진입·설정, 2026-10-26 사용자 요구)
계좌를 등록한 직후(처음 로그인) 그리고 설정에서 언제든:
1. 계좌를 **풀**로 묶는다: 합산할 계좌는 같은 풀에, 따로 갈 계좌는 각자 풀. 드래그 또는 체크박스
2. 풀마다 **전략**(올웨더 / K-올웨더 / 직접 설정)과 **모드**를 고른다
   - 리밸런싱: 매도·매수로 목표 비율을 맞춘다
   - 매수만: 매도 없이 납입금으로 부족한 자산군만 기계적으로 산다
3. 리밸런싱 화면 상단에 풀 선택 드롭다운. 화면은 선택한 풀 기준으로 그린다
현재 저장은 `rules/accounts.yaml`의 `pool` / `pools`와 기존 Streamlit 설정 화면이다. 전환 시 검증된 API와 DB로 연결하고 기존 계좌·풀·운용 모드를 이관한다.

## 구현 순서
- 기반: 합성 테스트·입력/저장/제약 검증 보강.
- 첫 시각 결과물: React 데스크톱·모바일 홈의 컨셉 재현, 고정 데모로 비교.
- 실제 연결: API·SQLite·계좌/보유/가격 → 입력·리밸런싱·결정 기록 흐름.
- 확장: 연금 실제 시뮬레이션, 부부 공유와 서버 권한 검증. 세금 설계·부동산 상세·승인형 자동주문은 후속 범위.
- 기존 Streamlit의 화면 완료 기록은 과거 PoC 이력이며 새 화면의 완료 기준이 아니다.


## 2026-10-27 추가 화면 요구 — 주식·부동산

- 주식·부동산은 독립된 사이드바 메뉴와 `#stocks`·`#property` 주소를 갖는다. 모바일 더보기에서도 같은 메뉴에 접근한다.
- 주식 기초 화면은 주식형 등록 자산만 표시하며 연금 안의 주식/일반계좌 주식을 구분한다. 주식 메뉴에서 등록하면 일반계좌·주식형으로 시작한다.
- 사용자 추가 요구(미구현): 종목·보유 수량·평균 매입단가를 한 번 등록하고 현재가를 가져와 평가금액·손익·수익률을 표시. 어제부터의 종목 뉴스(출처·발표 시각)를 모으고 호재/악재·상승/하락 영향 근거를 요약. 사실·추론·불확실성을 구분한다. 대상 시장/시세·뉴스 출처는 확인 후 연결한다. 현재 총액 입력을 종목 단위 기능 완료로 보고하지 않는다.
- 부동산은 사용자가 향후 고도화를 원함. 지금 집→가고 싶은 집을 중심으로 관심 단지 비교, 실거래가·매매/전세 흐름, 갈아타기 필요 자금과 월 저축액, 분양/교통/정비사업 뉴스를 연결하는 방향.
- 현재 부동산 화면은 실제 보유 지분과 등록 목록을 표시하고, 향후 기능은 고도화 예정으로 구분한다. 전체 대출을 주택 대출로 간주하지 않는다. 부동산 메뉴에서 등록하면 부동산 종류로 시작한다.


### 화면 템플릿 구현 — 2026-10-27

- 주식: 네이비 투자 저널 머리글 → 평단가·현재가·손익과 흐름 예시를 가진 종목 카드 → 투자 기준 메모 → 긍정/주의/지켜볼 소식 필터와 상세 창 → 기존 자산 원장. 가상 종목 4개의 수량×가격 합계는 기존 예시 주식 총액과 일치한다. 기간 선택은 가상 흐름 그림을 바꾼다.
- 부동산: 크림·세이지 톤의 CSS 건축 일러스트 → 지금 집/다음 집 → 가상 생활권 후보 3곳·관심/목표 선택 → 자금 계획 슬라이더 → 기존 보유 지분 목록. 목표 선택과 남은 기간/월 저축을 바꾸면 예시 계산에 반영된다.
- 부동산 자금 가정은 장부와 별도: 현재 집 매도 6억−주택 대출 1억, 이사에 쓸 현금 2억, 거래·이사 비용 3,500만원. 필요 자금 = 가상 목표 가격+비용−순매도자금−가정 현금. 예상 저축 = 월 저축×12×기간. 수익률·물가·개별 세금은 미반영. 실제 재무 시뮬레이션으로 보고하지 않는다.
- 실제 보기는 등록 금액만 표시하고, 종목별 시세/뉴스/목표 집이 미연결이면 빈 상태와 명시적인 예시 전환 버튼을 제공한다. 가상 종목·가상 뉴스·가상 주거지는 모두 예시 보기에서만 표시하며 저장하지 않는다.
- 검증: TypeScript/Vite 빌드, 브라우저 14개. 1440/1024/390/360px 화면·가로 넘침, 뉴스 필터/상세·종목 상세, 목표 집/관심/기간 슬라이더·예시/실제 분리. 사용자 시각 승인은 별도다.


## 2026-10-28 자산 등록 확인 화면 (REG-01, Claude)

- 레퍼런스: 사용자가 쓰는 증권사 잔고 화면(미래에셋 MY자산)의 정보 순서 + 토스식 평평한 꾸밈. AI 생성 화면 같은 장식(알약 배지·그라데이션 아이콘·영문 머리글·설명 카드)은 쓰지 않는다. 사용자 "AI 냄새가 나는 개발이 좀 그래".
- 계좌마다: 평가금액(크게) → 손익·수익률(하락 파랑/상승 빨강) → 매입금액·캡처 합계 대조 한 줄 → 자산군 비중 막대.
- 종목은 자산군별로 묶어 줄 세운다(사용자 "주식은 주식 티 나게, 금은 금 티 나게"). 묶음 머리줄 = 자산군 색 막대·이름·종목 수·소계·손익·비중. 묶음은 금액 큰 순, 미정 묶음은 맨 위. 종목 행은 두 줄(종목명·평가금액·손익 / 수량·평균단가·매입금액·수익률), 누르면 그 행만 입력칸.
- 나중에(사용자 요청): 자산군 묶음에 음영. Claude 해석 = 묶음 영역에 그 자산군 색의 아주 옅은 바탕(Streamlit 자산 시트의 계좌별 음영과 같은 방식). 다크 모드에서도 글자 대비 유지.
- 후보: 묶음 머리줄 옆 전략 목표("주식 78.8% · 목표 30%").
- 시안: claude.ai 아티팩트 '자산 등록 확인 화면 시안'(v3).

## 2026-10-28 엑셀처럼 입력·수정 (Claude)

- 사용자 요구: 자산을 엑셀처럼 손쉽게 입력·수정. 겉모양(리본·메뉴)이 아니라 칸의 느낌. 참고 excelstock.kr(엑셀처럼 보이는 시세 사이트).
- 앱 안 표: 열 문자(A, B…)·줄 번호·회색 격자·초록 선택 테두리·수식 입력줄(칸 주소, fx)·아래 시트 탭 두 장(보유종목 / 자산 — 구글 시트 탭과 같은 이름). 리본·메뉴 없음.
- 손동작: 칸을 누르고 바로 친다(한글 포함 — 보이지 않는 입력칸이 늘 선택 칸 위에 있어 IME가 그대로 들어간다). 화살표로 옮기기, Enter 아래로, Tab 오른쪽, F2·두 번 눌러 고치기, Delete 지우기, 줄 번호 눌러 줄 선택 후 Delete로 줄 지우기, Cmd/Ctrl+C 복사. 엑셀·구글 시트·증권사 화면에서 복사한 표를 붙여 넣으면 머리글 이름으로 열을 맞추고, 머리글이 없으면 고른 칸부터 채운다. 빈 줄은 늘 아래에 남아 있다(줄 삽입 메뉴 없음).
- 보유종목 탭: 계좌·종목명·종목코드·보유수량·현재가·매입금액·자산군·주식 구분 + 보여 주기만 하는 평가금액·손익(회색). 계좌 칸에서 '+ 새 계좌…'. 저장하면 바뀐 계좌만 그 계좌의 잔고로 다시 저장(검증은 서버가 다시).
- 자산 탭: 이름·계좌·보관처·소유자·나의 지분%·종류·자산군·금액·기준일. 사진·파일로 등록한 줄은 회색(보유종목 탭에서 고침). 공동은 부동산·대출만, 지분 1~99.
- 빨간 칸: 아래쪽 삼각형과 밑줄, 수식 입력줄 옆에 이유. 빨간 칸이 있으면 저장 잠김.
- 진짜 엑셀: '빈 엑셀 양식', '지금 잔고를 엑셀로 받기'(채워진 양식). 계좌·자산군·주식 구분은 엑셀 안에서 고르는 칸. 고쳐서 '엑셀·CSV 파일'로 올리면 계좌 열로 나눠 확인 화면.
- 들어가는 곳: 자산 등록 → '표로 입력·수정', 우리 자산·주식의 종목 잔고 → '엑셀처럼 고치기'.
