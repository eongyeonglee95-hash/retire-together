위키 = `docs/wiki/` (리서치 결과) + `docs/*_RULES.md` (제품 규칙) + `rules/*.yaml` (숫자의 원천).
사람이 읽고 고치는 지식이고, 나중에 큐레이터 Agent가 같은 절차로 갱신한다.

## 원칙

- **1차 출처만**: 저자 본인의 책 소개·블로그·유튜브·인터뷰, 운용사 상품 페이지, 국세청·금감원·KRX. 블로그 요약글은 출처를 찾는 단서로만 쓰고 인용하지 않는다. 열어서 읽은 페이지만 인용한다.
- **숫자마다 출처 링크**. 출처 없는 숫자는 "미확인"으로 표시한다.
- **책 내용은 요약**: 인용은 15단어 이내 한 번. 책에서만 확인되는 값은 "책 n장 확인 필요"로 표시한다.
- **제안과 결정 분리**: 위키는 제안한다. `rules/strategies.yaml`·`asset_map.yaml`에 넣는 건 사용자가 확인한 뒤. 페이지 끝의 "우리 적용" 블록이 YAML에 들어갈 후보 값이다.
- **추천 표현 금지**: "이 ETF가 좋다", "오를 것" 대신 "저자는 X를 쓴다", "적격 상품 목록은 Y". 전략·종목 선택은 사용자 몫.
- 기준일을 페이지 머리에 적는다. 세법·제도·상품은 바뀐다.

## 페이지 형식 (`docs/wiki/<폴더>/<slug>.md`)

```
# <제목>
기준일: YYYY-MM-DD · 상태: 초안 | 확인됨
## 요약 (5줄 이내)
## 룰 — 저자/제도가 정한 것
  자산군과 비율 / 리밸런싱 주기·임계치 / 적용 계좌·상품 / 저자가 말하는 이유
## 우리 적용 — strategies.yaml·asset_map.yaml 후보 값 (사용자 확인 전)
## 미확인 · 열린 질문
## 출처 (열어본 페이지만, 날짜)
## 변경 이력
```

폴더: `strategies/` 투자 룰(저자별) · `products/` ETF·계좌 상품(적격 여부, 기초지수, 보수) · `sources/` 데이터 출처(API·시세·공시)

## 새 주제: `/wiki-research <주제>`

1. `docs/wiki/README.md`에서 같은 주제 페이지가 있는지 본다. 있으면 update 절차로.
2. 출처를 연다. 저자 룰이면 저자 본인 채널 → 출판사 → 인터뷰 순. 상품이면 운용사 페이지 → KRX.
3. 페이지를 형식대로 쓴다. 완료 조건: 모든 절이 채워졌거나 "미확인"으로 명시됐고, 모든 숫자에 출처 링크가 있고, "우리 적용" 블록이 YAML 키 이름 그대로 적혀 있다.
4. `docs/wiki/README.md` 목차에 한 줄 추가. `docs/CHANGELOG.md`에 한 줄.
5. 사용자에게 보고: 확정 가능한 값 / 책 확인이 필요한 값 / 열린 질문 세 묶음으로.

## 재확인: `/wiki-research update [페이지]`

0. 이 절차는 `wiki-updater` 에이전트(`.claude/agents/wiki-updater.md`, Sonnet)에 맡긴다. 페이지가 여러 개면 페이지마다 하나씩 병렬로 띄우고, 결과 보고를 모아 사용자에게 전한다. 새 주제(위 절차)는 세션 모델로 직접 한다.
1. 대상 페이지(지정 없으면 `docs/wiki/` 전체 + `docs/TAX_RULES.md`)의 출처를 다시 연다.
2. 바뀐 것만 고치고, 페이지 "변경 이력"과 `docs/CHANGELOG.md`에 날짜와 함께 적는다. 바뀐 게 없으면 기준일만 올리고 "변경 없음"을 적는다.
3. `rules/*.yaml`에 이미 들어간 값이 바뀌었으면 YAML을 고치지 말고 사용자에게 알린다 (결정은 사용자).
4. 주기적 실행은 `/schedule` 또는 `/loop`로 이 명령을 걸어 둔다. 세법은 매년 1월, 상품·제도는 분기.
